# Настройка защищённой админки Olo'Kafu'áng

Подготовка проекта уже сделана. Supabase подключается к твоему аккаунту, поэтому первые шаги нужно выполнить самому. **Никакие пароли или секретные ключи мне отправлять не нужно.**

## 1. Создай проект

1. Войди на [supabase.com](https://supabase.com/) и создай новый проект.
2. Дождись, пока проект запустится.
3. Открой **Project Settings → API** и скопируй **Project URL** и **Publishable key** (или legacy `anon` key). Это публичные клиентские значения, их разрешено хранить в коде сайта.
4. Не копируй `service_role` или `secret` key: браузерный сайт с таким ключом небезопасен.

## 2. Создай таблицу и включи защиту

1. В репозитории открой файл [`supabase/setup.sql`](supabase/setup.sql).
2. Скопируй его целиком.
3. В Supabase открой **SQL Editor → New query**, вставь SQL и нажми **Run**.
4. Если появилась ошибка, остановись и проверь сообщение: не продолжай, пока SQL не выполнится успешно.

Скрипт загружает начальные данные сайта. Публичным посетителям разрешено читать их; изменять их через базу могут только авторизованные администраторы.

## 3. Создай администратора

1. В Supabase открой **Authentication → Sign In / Providers → Email** и отключи **Allow new users to sign up**.
2. Открой **Authentication → Users → Add user**. Создай пользователя со своей почтой и придумай ему **новый надёжный пароль**. Не используй пароль от GitHub или других сервисов.
3. В **SQL Editor** выполни запрос ниже, заменив `you@example.com` на эту почту:

   ```sql
   update auth.users
   set raw_app_meta_data =
       coalesce(raw_app_meta_data, '{}'::jsonb) || '{"role":"admin"}'::jsonb
   where email = 'you@example.com'
   returning id, email;
   ```

4. Убедись, что запрос вернул ровно одну строку с твоей почтой. Если строк нет или их больше одной — остановись и проверь адрес.

## 4. Подключи сайт

Открой `js/config.js` в репозитории и подставь полученные в шаге 1 значения:

```js
const CONFIG = {
    supabaseUrl: "https://ТВОЙ_PROJECT_ID.supabase.co",
    supabaseAnonKey: "ТВОЙ_PUBLISHABLE_ИЛИ_ANON_KEY"
};
```

Сохрани и отправь изменение в GitHub. **В этой конфигурации не должно быть `service_role` или `secret` key.**

До заполнения конфигурации сайт продолжает показывать данные из `data/default-data.json`, а админка остаётся закрытой. После подключения публичные страницы читают общие данные из Supabase.

## 5. Войди и проверь

1. Открой сайт и перейди в **Админка**.
2. Войди созданной почтой и новым паролем.
3. Проверь изменение названия, состава и сессии, затем открой главную страницу или обнови сайт в другом окне — данные должны совпадать.
4. Нажми **Выйти** и проверь, что форма входа снова показалась.

## Что защищено

- Пароль проверяется сервисом Supabase Auth, а не сравнением в JavaScript.
- Правила базы данных (RLS) защищают запись независимо от того, что делает интерфейс.
- Для входа доступны только созданные тобой пользователи, если регистрация отключена.
- Данные сайта публичны для чтения; не помещай в них личные или секретные сведения.
- Кнопка записи на сессию ведёт в Discord. Счётчик участников меняется в админке.
